# FactoryTestCases 界面视觉规范

## 脚本执行窗口（2026-10-08，2.9.10.8 恢复 2.22 历史实现）

- 最终检测本身没有独立面板；自定义项与实际 TestCases.bat 使用现有宿主私有执行器的同一个窗口。普通标题栏、Six6 图标、浅色 Mica、24 DIP 边距、160 ms 非阻塞淡入；正文采用清晰中性不透明表面，首帧完成布局后显示。
- 初始外框 1040×760 DIP，最小 760×540 DIP，受工作区限制。标题只突出脚本名、执行阶段和定位范围；中部为时间/原始源码/执行情况，含原始行号、注释和空行，代码等宽字体、长行折行、溢出纵向滚动。无输出面板、编辑框或手动 PASS。
- 运行行浅蓝，非零返回显示原值，整体失败后最近非零记录浅红；失败证据与退出行分别定位，不能把返回码或最后行伪称为根因。复合语句明确范围及未单独跟踪；无可靠记录则明确未确认，不生成虚假的逐行成功/失败。
- 自动跟随默认开启，手动滚动暂停跟随；定位/查看退出行、复制所选行或全文可用。底部按钮窄窗口分成两行，支持鼠标、Tab、Enter/Space。只刷新状态变化，源码双缓冲绘制，表头保持稳定。
- PASS/CANCEL 关闭，FAIL 保留供检查；运行中取消清理进程，已完成窗口关闭不改变结果或卡住自动队列。窗口私有用例覆盖中英越、长行、空源码、最小/最大化和 100%–200% DPI 参数，真实 DPI 与消息注入证据分别记录。

## 1. 适用范围与强制性

本规范是宿主和所有内置测试窗口的强制视觉基线，约束颜色、字体、间距、圆角、标题栏、按钮、输入框、表格、滚动条、绘制层级、控件状态和布局验收。新增测试模块、为已有模块增加窗口或修改窗口布局前，都必须先核对本文并沿用当前基线。

当前生产程序以及已经按用户反馈完成美化的窗口是实际效果基准。本文参数与当前实现冲突时，不得用过时文档覆盖已确认效果；应先按当前实现检查差异，并在同一项更新中同步修正文档。未经用户明确同意，不得自行恢复旧式重边框、整块白色卡片堆叠、固定蓝色表格背景、无用途空白列或其他旧样式。

本规范只统一视觉参数和交互规则，不建立共享 UI 业务架构。各测试模块继续在自己的目录内独立实现和维护窗口；未经明确同意，不新增跨模块 UI 静态库、公共窗口业务基类、窗口控制器或共享可变状态，也不得引用其他测试模块的窗口实现。

界面调整不得改变配置含义、设备枚举、测试步骤、线程、模块通信、日志内容、进度、PASS/FAIL/CANCEL 判定、窗口关闭或资源清理逻辑。有意偏离本规范时，必须先取得用户明确同意，并在对应模块文档中记录原因。

## 2. 视觉方向

- 以 Windows Fluent Light 的中性浅色和低干扰层级为基础，保持原生 Win32 程序的清晰度和响应速度。
- 使用紧凑、信息密度高的菜单与表格；悬停和按下反馈必须清楚可辨，但不能用大面积强色抢占内容注意力。
- 主窗口底层、侧栏、标题栏与工具栏采用浅色系统云母（Mica）。使用 SDK `SystemBackdrop` 管理系统材质，背景绘制保留透明通道；日志和电脑信息采用清晰的浅色内容层。不使用静态蓝紫光斑、人造彩色渐变或实时截图模糊。系统不支持材质时回退到浅色底色，Windows 也可按透明效果、节能和焦点状态呈现自己的实色回退。
- 卡片只用于确实需要分组的主面板，不在整个子窗口内容外再套一层大白色卡片，也不连续嵌套多层卡片。
- 按用户 2026-09-24 的明确要求，接入本地 FluentUI 0.2 原生 Win32/Direct2D 静态 SDK，固定浅色云母主题。主界面操作按钮和系统材质使用库控件；其余窗口在各自实现内读取 SDK 的 `DesignPalette` / `ControlPalette`。不引入 Qt、QML 或额外 UI 运行时，不共享窗口业务类、设备状态和控制器。系统字体仍使用 `Segoe UI` 及 Windows 字体回退。

## 4. 宿主视觉基线

- 标题栏高 44 DIP。右侧最小化、最大化/还原和关闭按钮均使用 44 × 44 DIP 命中区，图标在同一矩形内严格水平、垂直居中。
- 标题栏按钮图标使用 10 DIP 系统字形，优先选择 `Segoe Fluent Icons`，旧系统回退到 `Segoe MDL2 Assets`。关闭按钮只在悬停或按下时显示红色背景；最小化和最大化按钮常态透明，悬停和按下分别使用窗口按钮令牌。
- 无边框主窗口由 `WM_GETMINMAXINFO` 将最大化外框限定在当前监视器工作区，`WM_NCCALCSIZE` 保留整个矩形为客户区，不再重复内缩缩放边框。客户区原点与工作区原点一致，不能留下未绘制的外圈。
- 主窗口使用预乘 Alpha 的 D2D 目标，并将系统材质扩展到客户区；使用不含 `WS_CAPTION` 的 `WS_POPUP` 可调整大小窗口，保持 `DWMNCRP_ENABLED`，不能通过关闭 DWM 非客户区渲染来隐藏系统标题栏。自绘边缘拦截 `WM_NCPAINT`，`WM_NCACTIVATE` 保留激活处理但禁止默认重画，`WM_ACTIVATE` 重新应用材质扩展。前台、失焦、再次激活均不得出现白色外框。RichEdit 日志保持独立的不透明子表面。
- Fluent 工具栏 Host 同时启用 `compositionSurface` 与 `transparentBackground`，按钮间隙和外围不铺独立白色矩形，直接显示主窗口材质。
- “开始全部 / 暂停测试 / 清空日志”使用 FluentUI 原生 Button：高 36 DIP、间距 8 DIP、圆角 4 DIP。开始为蓝色强调按钮，其余为浅色标准按钮，保留悬停、按下、禁用、Tab 焦点及 Enter/Space 操作。中、英、越按钮宽分别为 96、116、180 DIP；命令仍进入宿主原有启用条件与处理路径。
- 当可用宽度不足以同时容纳操作按钮和右侧窗口按钮时，工具栏扩展为 96 DIP，三项操作移到第二行；中英文和越南文按各自所需宽度布局，不能与窗口按钮重叠或被截断。
- 左侧测试列表行高 44 DIP、步长 46 DIP、圆角 6 DIP，无常驻卡片边框。WAIT 只显示前置图标；RUN 显示必要的文本/百分比进度；PASS、普通 FAIL 和 CANCEL 终态只保留单行名称与右侧状态，不再重复显示“检测通过/检测失败/已取消”等第二行说明。配置错误原因以及启用 `FailLock` 后的失败次数/锁定提示可以保留。
- 菜单悬停使用清楚可辨的浅蓝色，文字保持深色，不得使用与云母底色接近的浅灰。Logo 绘制矩形距顶端 16 DIP（比 1.10 版上移 12 DIP），宽 172 DIP，保持比例；“测试项目”和菜单起始位置不随之移动。
- RUN 行使用淡蓝背景、左侧 3 DIP 品牌蓝短条，百分比进度条位于行底部。窗口正常显示且操作员未拖动测试列表滚动条时，进入可视区之外的新运行项目必须自动滚动到可见位置；窗口最小化或拖动期间不得抢夺滚动位置。
- 主面板圆角 8 DIP、1 DIP 弱描边和约 2 DIP 向下的弱阴影；标题区高 56 DIP，不放无必要的解释性副标题。
- 交互式测试列表滚动条常态宽 3 DIP，悬停或拖动时扩展到 6 DIP，实际鼠标命中区不得小于 12 DIP；只读电脑信息滚动条保持 3 DIP。滚动条只在内容溢出时出现。
- 主界面电脑信息采用紧凑的标签/值两列、轻微交替底色和弱分隔线；标签列约占可用宽度 24%，并限制在 84–112 DIP，行高至少 42 DIP且随长文本增加。不显示多余分类列、空白表头或可拖动的空白尾列。
- 主界面不绘制蓝色或紫色环境光背景；内容层级依靠中性背景、间距、描边和轻阴影建立。

## 5. 测试模块窗口模式

### 5.1 通用规则

- 普通测试窗口先准备完整首帧（含原生子控件和 Direct2D 内容），再用约 160 ms 的三次缓出淡入。计时从 UI 消息循环能够更新画面时开始，不能在其他并行窗口还在创建时提前耗尽动画时间；不能用 Sleep 或阻塞式动画延迟测试线程、输入和测试判定。每个窗口实现分别维护自己的短期定时器和透明度状态，完成后恢复普通不透明窗口，关闭时由窗口生命周期清理定时器。
- 首帧保留必要的同步完整绘制；已经准备首帧后不要立即重复 `UpdateWindow`。淡入结束只请求正常重绘，不再强制同步重画整个客户区和子控件。频繁快照按最新状态合并 UI 通知；窗口释放完自身资源后才通知工作线程关闭完成，UI 线程自身执行关闭时不得依赖自己稍后才能消费的消息。
- 系统关闭客户区动画或启用高对比度时直接显示；视觉准备失败只回退普通显示，不能使测试 FAIL。相机视频表面、屏幕检测色彩图案和外接屏数字覆盖层保持原来的直接不透明显示，避免透明度改变真实测试画面。
- 多个测试弹窗出现时，本程序的普通弹窗与主窗口应保持连续层级：当前测试弹窗在上，其他测试弹窗保持原有顺序，主窗口在下。宿主只通过原生 `GW_OWNER` 链识别自己的顶层窗口，在激活交接后调整这些窗口的 Z 序，不访问测试控件或业务状态。激活消息合并为一个待处理请求，窗口已经相邻时不重复调整。不能修改其他进程窗口、永久置顶、抢回焦点或恢复已最小化的窗口；用户切换其他应用后停止调整。
- 测试模块窗口使用普通 Windows 标题栏、生产程序 `Six6.ico`、Per-Monitor V2 DPI 和当前显示器的系统消息字体。窗口客户区采用与宿主一致的中性浅色主题。
- 模块的中性色、品牌色、文字和输入框边框从本地 SDK 视觉令牌读取；每个实现保留自己的颜色转换函数。音频窗口的次要操作采用浅色按钮与深色文字，相机的操作区采用浅色表面，图像/视频区域继续保持黑色。屏幕检测图案、外接屏数字及 PASS/FAIL 信号色不跟随装饰主题替换。
- 音频窗口按用户提供的 WPF-UI 参考采用系统 Mica 与局部半透明卡片，GDI 自绘按钮必须使用独立不透明子表面，避免文字被玻璃合成吞掉；每项独立持有 SDK 材质、绘制资源和按钮。
- 键盘测试、键盘布局编辑器及手柄测试在 2.10.10.8 修复相同合成问题：直接放在云母客户区的 GDI 自绘按钮分别使用不透明子表面和随 DPI/尺寸更新的圆角区域，父窗口淡入结束后恢复并重绘子表面。编辑器左侧已有不透明面板内的控件保留原绘制方式。视觉验收须观察桌面实际合成画面，单靠控件文字、布局断言或 PrintWindow 不能证明按钮在 Mica 上可见。
- 整个窗口客户区不得再包裹一张大白色卡片。只有确实需要区分输入区、结果区或操作区时才使用局部表面，并保持层级不超过一层。
- 标题、说明、状态、表格和操作按钮应在初始尺寸内完整显示；底部操作区不能被表格或滚动条遮挡。
- 控件按可见内容和光学中心线对齐。标签、编辑框、组合框、复选框和按钮内部边距不同，不能仅因外框 `y` 坐标相同就认定已经对齐。
- 普通、悬停、按下、禁用和键盘焦点必须各自可辨；禁用状态不能只靠把透明度降低到不可读。

### 5.2 信息与扫描表格

- 视觉参考主界面“电脑信息”：浅色正文、轻微交替行底色、弱分隔线和紧凑行高，不使用旧式重网格或厚表头边框。
- 表头必须与当前主题一致，不得保留系统旧式高对比凸起表头。正文不能因默认选择状态长期显示固定蓝色背景；蓝色只用于真实选择、焦点或 RUN 状态。
- 只创建有业务含义的列。不得保留无内容的分类列、空白表头或最右侧可拖动的占位列；所有有效列的总宽度应填满可用客户区，并为垂直滚动条预留宽度。
- 行高应以能稳定显示单行文本和状态图标为准，避免因过高导致目标信息无法在初始窗口内完整显示。长内容可换行、省略或显示 Tooltip，但不得修改原始数据或测试判定。
- 调整窗口大小、切换 DPI 或更新数据后必须重新计算列宽；不能出现表头与正文错位、尾部空白区域可拉伸或滚动条覆盖最后一列。

### 5.2.1 蓝牙与 Wi-Fi 扫描窗口

- 两个模块各自采用浅色系统 Mica、普通系统标题栏和私有 Direct2D 摘要区。顶部标题 24 DIP，说明 13 DIP；页面边距 24 DIP，三个摘要卡片间距 12 DIP、高 80 DIP，圆角 8 DIP、半透明白色弱描边；摘要值约 22–26 DIP。
- 蓝牙显示已发现数量、快照已达标数/配置要求数、最低 RSSI；Wi-Fi 显示已发现数量、快照的 2.4 GHz/5 GHz 达标状态，Single 的 5 GHz 显示“无需检测”。只展示原有快照，不引入 UI 计时、连接控制或新判定。
- 表格区域与摘要相隔 16 DIP，顶部有列表标题和最强 RSSI 说明。表头高 38 DIP、正文行高 36 DIP、文本 14 DIP，沿用平面表头、浅色交替行及弱分隔线。列表保留原生滚动、选择和长文本 Tooltip；未发现项目时显示扫描提示。
- GDI 表格使用独立不透明子表面，在淡入完成后重绘；表头直接在自己的绘制周期完成，避免透明文字、旧式凸起或额外竖线。刷新应合并绘制并保持滚动位置。
- 蓝牙初始约 `880 × 620 DIP`、最小约 `680 × 480 DIP`；Wi-Fi 初始约 `960 × 640 DIP`、最小约 `760 × 480 DIP`。地址及 RSSI 等短字段优先分配足够宽度，名称/SSID 弹性填满剩余视口；不新增状态列或空白尾列。

### 5.2.2 驱动检测窗口

- `CheckDrives` 沿用扫描窗口的系统 Mica、摘要卡片、平面列表、字体、行高和淡入。初始约 `960 × 640 DIP`，最小约 `820 × 480 DIP`；三语布局包含驱动数、已检查设备数、非白名单异常项数和当前阶段。
- 标题下方为 4 DIP 高的品牌蓝循环 loading 条，运行期间持续移动，仅表示工作中，不表示完成百分比，不参与测试进度或判定；FAIL 时停止。右上角运行中显示“正在检测”，失败展示期间显示红色 FAIL。

- 键盘测试使用系统浅色 Mica、普通系统标题栏及 Six6 图标；顶部标题 24 DIP、说明 13 DIP、完成数量 24 DIP，页面边距 24 DIP。布局按 KBL 几何比例显示，按键圆角 5 DIP、弱描边；等待浅灰，按下浅蓝，通过浅绿，重试浅黄。底部保留 36 DIP 高的重新测试与结束按钮。
- KBeditor 是单独的原生工具，各自维护窗口与业务。默认空白，不自动打开 Main.KBL；顶部为新建、打开 KBL、保存、另存、撤销、重做和预览，窄窗口换成两行。编辑区占主面积；左侧常用面板显示名称、绑定与直接操作，坐标和扫描码等收进可滚动的详细属性。
- 连续添加只点击一次，仅鼠标“下一行”操作改变录入行；超出当前宽度时横向扩展布局并按比例显示，不按窗口宽度或固定按键数量自动换行。选中描边为品牌蓝，右下角显示尺寸拖动点；拖动时固定几何缩放，双击进入实际按键重新绑定。名称与绑定采用清晰的不透明原生控件表面，不能因 Mica 的 GDI Alpha 使文字透明；编辑器清单包含 Windows 10/11 兼容声明，淡入结束重新确认分层子表面不透明。
- 编辑器初始外框约 1220×760 DIP，最小约 920×520 DIP；测试初始客户区约 1040×580 DIP，最小外框约 680×480 DIP。初始及最小尺寸均限定于当前屏幕工作区。长文本换行或省略，属性面板内容溢出时滚动；中、英、越三语分别检查。
- 窗口各自保留 160 ms 非阻塞淡入和高对比度/关闭动画回退。没有在界面、状态或关于页添加版权或作者文字。

## XBOX/掌机测试窗口（2026-10-03，2.11）

- 普通标题栏、浅色系统 Mica、160 ms 首帧淡入、24 DIP 页面边距；初始客户区 1080×720 DIP、最小外框 680×480 DIP，受工作区约束。取消双 Tab，设备选择与底部状态固定，中间为一个测试视口。
- 正式模式使用模块私有 Direct2D 贝塞尔手柄外形；ABXY、方向、LB/RB、View/Menu、两个摇杆和 LT/RT 在对应位置显示。等待中性灰、实际按下蓝、通过浅绿；摇杆保留 16 个外圈采样点、实时位置和转圈/点击状态，扳机显示实时深度及到底/松开结果。统一等比例缩放、不拉伸手柄。
- 震动启用时仅在 LT/RT 测试内按深度输出和显示幅度；没有独立震动页或左右确认按钮。所有标准及自定义自动检查完成、电机归零后弹出一次同模块拥有的人工确认窗口，明确正常 PASS、异常 FAIL，关闭确认窗口为 CANCEL；其外观和三语字体沿用主测试窗口。
- 自定义区域在宽视口右侧，窄视口移到手柄下方；显示当前配置目标、已完成数量和紧凑绑定列表。标准项目完成后才测试自定义目标，每项需要新的周期；长名称/绑定省略并保留完整列表提示，窄窗口允许滚动。
- DebugInput=1 是独立持续诊断模式：主内容只显示调试表，不显示手柄图、生产进度、自定义判定或震动确认；保留必要的手柄/HID 选择、复制/清空/关闭。新事件追加及定长替换均强制滚到最新行，空闲刷新不改变历史浏览位置。轴数值也在表内显示，可复制按钮/报告位等有效配置标识。
- 表头缓冲绘制，采样只重绘变化行区；相同条数、列宽、选择与尺寸不反复设置。GDI 表格、下拉框保留不透明子表面，展开时保留鼠标待选值。HID 报告位与 Windows 按钮数组明确区分，不猜测原生背键含义，也没有型号写死的接口优选或厂商状态提示。
- 正文 13 DIP、标题 24 DIP、弱描边、灰阶文字抗锯齿；核对中英越、长文本、空值、初始/最小/最大化、首帧和 100%–200% DPI，实际观察范围写入版本记录。

## 6. 表面与装饰边界

- 标题栏、工具栏和面板表面使用稳定中性色，不绘制会随窗口尺寸显得变形的彩色环境光斑。
- 日志、表格、测试名称、硬件信息值和输入框后方不得使用实时模糊、透明折射或动态渐变。
- 阴影只用于主面板等真实层级边界；普通标签、表格单元格、按钮文字和输入说明不得带阴影或光晕。
- 远程桌面、透明效果关闭或性能不足时，界面必须自然保持为不透明浅色，且布局、文字和命中区域不能变化。

## 7. 遮挡与变形验收

每次宿主或模块 UI 更新必须实际观察并记录：

- 中文、英文、越南文。
- 最大化、初始还原尺寸和允许的最小尺寸；最大化后客户区不得向屏幕外偏移。
- 100%、125%、150%、175%、200% DPI；没有对应环境时必须明确标记未实测。
- 普通、悬停、按下、禁用、键盘焦点、RUN、PASS、FAIL、CANCEL 和配置错误状态。
- 长文本、空值、多行值、列表首尾、滚动条、第一帧和窗口跨屏 DPI 切换。
- 所有标题、按钮、输入框、表头、正文、状态、底部操作区和滚动条不得互相重叠、被窗口边缘遮挡、被错误拉伸或压缩。
- 表格不得出现无用途空列、空白表头、固定蓝色正文背景、表头与正文错位或可拖动的空白尾部。
- 主窗口运行项必须自动进入可视区；终态列表不得重新出现重复结果说明。

宿主可使用 `FactoryTestCasesHostUiVisualSmoke` 和 `tests/host/dense_ui_config.ini` 做可见密集布局检查；带窗口的测试模块应提供不进入生产注册表和交付包的确定性视觉冒烟入口。视觉冒烟和自动测试不能替代目标工厂机及全部 DPI 档位验收。

## 8. 后续测试项接入清单

1. 开始实现前选择本规范中最接近的窗口模式，并在模块设计记录中写明表格、录入、数字作答或人工确认类型。
2. 在模块目录内独立实现窗口，复制必要的视觉参数，不引用其他测试模块的窗口代码，也不为统一样式新增共享业务 UI 层。
